# Cognitive Forensics: Bounding and Auditing Agentic Execution

**Status:** DRAFT
**Version:** 1.0
**Source spec:** [truth-root.md](truth-root.md), [grace-contract.md](grace-contract.md)

## Abstract

This document defines the architectural specification for **Cognitive Forensics** within the ecr-wg environment. When an autonomous agent executes a work product, the system must generate a tamper-evident audit trail that allows an operator or a forensics team to reconstruct, isolate, and verify the execution. 

We reject the naive assumption that LLM outputs can be perfectly replicated. Instead, we establish a tripartite division of execution boundaries—the Permitted, the Possible, and the Probable—and define the cryptographic binding between Agent Enrollment Cards, EMILIA Protocol (EP) Action-Control Manifests, and the output Signature Blocks.

---

## 1. The Forensics Triad

Verifying or auditing an agentic event requires separating deterministic constraints from probabilistic behaviors. We define three distinct operational tiers:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          THE FORENSICS TRIAD                            │
├─────────────────────────────────────────────────────────────────────────┤
│  1. THE PERMITTED  │ Cryptographic & Deterministic │ EMILIA Receipts    │
├────────────────────┼───────────────────────────────┼────────────────────┤
│  2. THE POSSIBLE   │ Structural & Environmental    │ Sandboxes / MACs   │
├────────────────────┼───────────────────────────────┼────────────────────┤
│  3. THE PROBABLE   │ Distributional & Stochastic   │ Model Inference    │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.1 The Permitted (Deterministic / Cryptographic)
*   **Definition:** What the agent was explicitly authorized to do at the exact moment of execution.
*   **Enforcement:** Cryptographically frozen by the EMILIA Protocol (`EP-RECEIPT-v1`).
*   **Forensic Properties:** 100% reproducible. The receipt states the exact action, the target bytes (via Merkle anchors/digests), the authorization authority, and the time boundary. You do not need to re-run the model to prove authorization.

### 1.2 The Possible (Structural / Environmental)
*   **Definition:** What the agent was physically capable of doing based on the operating system, network routing, and file system permissions.
*   **Enforcement:** Bounded by OS sandboxing, directory isolation, read-only mounts, and the `EP-ACTION-CONTROL-MANIFEST` (`agent-action-control.json`).
*   **Forensic Properties:** 100% reproducible. The boundaries are environmental constraints. An agent without network access cannot connect to a socket, regardless of the prompt.

### 1.3 The Probable (Distributional / Stochastic)
*   **Definition:** The actual cognitive reasoning and text generated by the LLM substrate.
*   **Enforcement:** Guided by Layer 1 (Substrate Physics) and Layer 3 (Persona Overlays).
*   **Forensic Properties:** **Non-deterministic.** Silent provider updates, hardware float non-determinism, GPU driver variations, and sampling temperature mean the exact token sequence cannot be guaranteed on a re-run. Forensics must treat this as a *probability distribution* over $N$ runs, rather than a single static value.

## 2. Card-to-Manifest Cryptographic Binding

To prevent identity spoofing and scope creep, an agent's public enrollment card must cryptographically bind the agent's identity to its authorized operational envelope.

```
  [Enrollment Card] ──(binds to digest)──> [Action-Control Manifest]
         │                                         │
         ▼                                         ▼
   (Who is the agent)                       (What is permitted)
```

### 2.1 The Agent Action-Control Manifest (`agent-action-control.json`)
Located in the repo's `/.well-known/` directory or referenced by URI, this file declares the agent's authorized scope using machine-readable contracts:

```json
{
  "agent_id": "E-4B7E4B91-1849-001",
  "scopes": [
    {
      "action": "git_commit",
      "consequential": true,
      "assurance_tier": "CF-1",
      "paths_allowed": ["/enrollments/*", "/planning/*"],
      "args_allowlist": ["-m", "--amend"]
    },
    {
      "action": "supabase_query",
      "consequential": false,
      "assurance_tier": "CF-0",
      "tables_allowed": ["strains", "orders"]
    }
  ]
}
```

### 2.2 The Enrollment Card Reference
The agent's public enrollment card (`enrollments/agent-XX.md`) MUST contain a SHA256 digest of its active Action-Control Manifest. Any changes to the manifest invalidate the binding, requiring a new operator ratification.

## 3. The Forensic Signature Block

Every work product produced by an enrolled agent must carry a self-contained, tamper-evident signature block. This block serves as the "packing slip" that a forensics team extracts to verify or replay the event.

```text
<!-- AGENT-SIGNATURE
agent_id: E-4B7E4B91-1849-001
thumbprint: 4A15B6F7ABCC89B1
manifest_digest: A7C5E9B2F83D164E...
ep_receipt: EP-RECEIPT-v1.eyJhbGciOiJSUzI1NiIsImtpZCI6Ik...
input_context_digest: B38F9E2A01CD8B7F...
output_digest: D8F9E23B095A64C1...
timestamp: 2026-07-02T00:22:00Z
-->
```

### 3.1 Verification and Reconstruction Loop
When an auditor extracts this block, they can run a static verification pass without invoking an LLM:

1.  **Validate the Receipt:** Verify the `ep_receipt` against the EMILIA issuer public key. This proves the action was cryptographically authorized.
2.  **Verify the Manifest:** Fetch the manifest matching the `manifest_digest` from Git history. Confirm the executed action conforms to the allowed paths and arguments.
3.  **Confirm Input/Output Integrity:** Recompute the SHA256 hashes of the files read during the session and compare them to `input_context_digest` and `output_digest`. Any modifications to the files after the event will result in a mismatch.

If the static verification passes, the audit trail is valid. The team can then proceed to rebuild the container matching the `git_commit` at that timestamp to perform stochastic analysis of the reasoning layer (running the model 500 times to study the output distribution).
